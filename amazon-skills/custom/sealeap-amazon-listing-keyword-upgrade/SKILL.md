# 亚马逊 Listing 关键词全面升级

把用户指定的单款商品改写成目标站点语言。核心偏好：**优先使用用户词表，在真实、相关、通顺的前提下，将可自由扩写的文案字段写到接近最新有效限制；先完整审核，再按明确授权发布。**

这不是某个 ASIN 的固定文案模板。店铺、参数、竞品功能和字数上限每次重新确认。

## 1. 先确认范围并保存原文

- 确定店铺、Seller ID、站点、marketplace ID、子 ASIN 和对应 SKU。广告 profile 的 scope 不能当作 Listing 的 amazon_store scope。
- 优先发现并使用多宝鱼 MCP 当前工具和内部技能。可用时搜索、加载 `amazon-listing-optimization`；需要发布时再加载 `listing-direct-creation`。先读取实际工具 schema，不照搬旧参数。
- 用 `listing_get_live` 读取 summaries、attributes、issues，保存标题、Highlight、全部五点、描述、后台词、型号、尺寸、变体和报价等原值。过滤认证信息及带签名下载地址后再存档。
- 后台词字段未返回、空值、读取失败要分别说明；未返回不等于整个目录没有关键词或索引。原值未知时，发布前尽量通过已有授权的后台环境补齐备份，并说明恢复旧值的局限。
- 用户没有指定的价格、库存、变体、类目、图片、A+ 不自动纳入发布。
- 遵守本项目的数据源优先顺序。MCP 能力缺失或失败时，先检查范围、参数、权限、同步；有限重试后再说明原因并回退。不得绕过接口权限或确认约束。

## 2. 固定自身事实，借鉴竞品表达

建立“参数 / 本品证据 / 是否可改 / 待确认项”表：

- 自有电压、容量、能量、尺寸、重量、持续电流、循环、温区、包装内容和功能优先；不能拿竞品数值覆盖本品。
- 用户解释过的历史型号、清关标识或内部编码保持原样。某个型号含 BT 等字样，不足以推断实物支持相应功能；按实物证据和用户已确认的版本定位写消费端文案。
- 对标用户指定的竞品，而非擅自换成流量更大的其他款。读取目标站点的标题、五点、规格和卖点；收费接口在调用前说明预计次数和计费性质。
- 可借鉴需求、场景、功能解释顺序、安装问题和选型表达，独立改写，不复制竞品整段文字。
- 竞品的蓝牙、自动加热、低温断充、阻燃、认证、寿命、保修、串并联能力等，须有本品依据才能写。工作温区不等于自动保护功能。
- 区分当前官方属性、现有图片声明、第三方竞品资料和用户确认。图片与文字冲突时标待核实，不默认较强声明真实。
- 场景兼容要写明电压、电流、峰值、接口或安装条件；不能把“可在适当系统中使用”写成“所有设备通用”。额定能量不等于保证续航时间。

## 3. 把字符限制真正查清楚

每个站点、类目分别核实标题、Highlight、每条五点、描述和后台词：

1. 调 `catalog_get_product_type` 读取当前 product type 的字段名、硬约束、帮助文字及版本。
2. 查目标站点当前 Amazon 官方规则及生效日期。不要只用旧公告、搜索摘要或第三方字数工具判断。
3. 建表：字段、schema 限制、最新政策、采用限制、字符或 UTF-8 字节、来源和核实时间。
4. schema、帮助文字、搜索收录限制或前台规则不一致时，区分说明，采用适用的更严格限制；可做零写入 VALIDATION_PREVIEW 验证草稿，不把接口放行当成全部政策或索引保证。
5. 不把建议长度当成硬上限，也不把接口可接收上限当成前台合规上限。

已知校准案例，**使用前仍需核实**：
- Amazon 意大利站 2026-07-27 生效公告规定，非多媒体主标题最多75字符，Highlight125字符。某些 schema 仍返回标题200，不能据此写200字标题。
- 某 AUTO_BATTERY schema 的五点硬字段为700字符，但帮助文字另写100；应披露差异，并以实际验证结果说明可提交性，不推广为所有类目的统一规则。
- 后台搜索词的输入 schema 可能比搜索系统规则宽。意大利站官方规则为少于250字节时，总量最多249 UTF-8字节；不能把多个框的上限相乘扩容。

官方核验入口：
- [意大利站标题与 Highlight 公告](https://sellercentral.amazon.it/seller-forums/discussions/t/3ce5a947-a4c5-4e94-9480-cdbc7262dcc0)
- [意大利站搜索词规则](https://sellercentral.amazon.it/gp/help/external/G23501)

逐字段用脚本精确计数，空格、标点、换行均按实际提交文本计入；加粗等审核标记不进入提交文本。Python 可用 `len(text)` 和 `len(text.encode("utf-8"))`；不要把一个意大利重音字母一律算作一个字节。

## 4. 按用户词表扩写，而非换一套词

把用户提供的词逐个分类：核心品类与规格、相关功能、场景/组件、需条件解释、规格错误、无关意图。

- 标题优先品牌、核心购买词、准确规格和型号；Highlight承接场景或差异信息。检查站点对重复词、特殊符号和字段间冗余的限制。
- 五点各有主旨，但允许自然覆盖多个相关短语；描述补充兼容、安装、使用边界与选型解释。
- 尽量保留用户给定词形和短语。需要变词序、加介词或用单复数变体才能通顺时，优先自然目标语言，在覆盖表中写“语义/词干覆盖”，不要伪称完整短语命中。
- 在用户要求充分利用字符时，以接近上限为目标，通常可争取95%左右或以上的有效用量；这是写作目标，不是强制配额。不能靠重复同义规格、无意义凑字或新造卖点补满最后几个字符。确实无法接近时解释原因。
- 正文中嵌入组件关键词时说明关系，例如“通过兼容控制器连接太阳能板”，避免让人误以为组件随箱附送。
- 错误容量、不同化学体系和无关类目词不冒充本品。比较或替换词仅在真实、有条件的解释语境中使用；不能为了埋词强行写否定句。
- 后台词优先取用户词表里的相关词及尚需补充的别名，按最新规则去重、去无关词、控制总字节；不放竞品品牌，不为“填满”而堆重复单词。
- 给出每个原始关键词的新位置、完整/部分/语义覆盖或排除原因。文本覆盖不等于索引，零写入校验也不证明已收录。

## 5. 交付可直接审核的完整稿

先讲清实质变化、限制和待核实事实，再逐框列出：

- 完整目标站点语言标题、Highlight、五点、描述、后台词，不能只写修改建议。
- 用户关键词在审阅文本中加粗，便于一眼找到；另存不含 Markdown/HTML 标记的干净提交稿。
- 每框的实际字符/字节数、采用上限和用量比例；整套稿统一标版本，避免把不同版本混着提交。
- 当前原文与新版对照、竞品借鉴边界、全量用户词表覆盖表；保留参数不变清单。
- 图片/A+如有建议，另标“建议”，不要把文字审核当作资产发布授权。需要制作A+时选定模块后再核实各模块限制，不把描述框2000字套给A+。
- 用多宝鱼内部技能产出报告时，加载当前 `duobaoyu-report-spec` 并遵守适用格式，在用户指定目录保存自包含HTML及来源；同时按用户要求在聊天里列出完整加粗稿。不要将用户“先列出”误解成可以省略正文。
- 缺数据写清，不为文案改写虚构搜索量、评论痛点、类目基准或收益提升。没有性能数据时不强行判定流量/转化瓶颈；有数据也须区分相关性和因果。
- 用户要求先审核时先交稿，等审核完成再按其节奏询问是否发布；不在交付初稿时自动执行。

## 6. 执行已批准版本并独立核验

用户明确批准店铺、ASIN及具体稿件后：

1. 重新读真实Listing，核对身份、当前原值、现有问题和实际差异。
2. 仅为已批准的字段构造最小JSON Patch；型号、价格、库存、变体、图片/A+等不顺带修改。保留字段与替换字段分开记录。
3. 调 `listing_prepare_change` 做零写入预览。区分 VALID、ERROR、WARNING、权限失败和计划失效；依据错误修正，有限重试，不反复猜字段。
4. 把预览对应的完整内容与目标店铺交用户确认。已有明确确认且新预览内容完全相同时，在当前MCP确认规则允许下不重复索要许可；内容改变、权限要求重确认或需要新增字段时重新展示确认。遵守当前工具对计划过期和重新确认的规定。
5. 用户批准后才调 `listing_execute_change`。用不含格式标记的干净稿，不用报告里的带粗体版本。
6. 用 `listing_get_live` 独立读回，逐条核对标题、Highlight、五条五点、描述、后台词；核对用户要求保留的型号、报价、库存和变体等是否未变，检查新增问题。
7. 如执行返回不确定结果，先读回再考虑重试，避免重复提交。遇到抑制或实质错误时说明影响，只在已授权范围内修复；恢复也需当前MCP要求的预览确认流程。

正确区分交付状态：
- VALID：预览通过，未提交。
- ACCEPTED：Amazon已接收，不能直接说前台全部生效。
- attributes匹配：卖家提交属性已读回一致。
- summaries或前台仍旧：目录/页面传播尚未完成，写明已核验层级；做少量有间隔复查，不无限轮询，也不自动创建定时任务。
- 索引与排名：单独验证；不可由属性写入成功推出。

最终报告已更新店铺/站点/ASIN、字段成功/待同步/失败数量、保留字段、现有及新增警告、前台同步局限，并保存预览、提交响应、修改前值及读回结果供回滚。只发布通用skill时，不把这些实际店铺数据、业务报告、凭证或具体执行计划带入公开仓库。

## 调用方式

“使用 `$sealeap-amazon-listing-keyword-upgrade`。店铺和站点为我指定的范围，目标ASIN及竞品另附；按本品参数和我的关键词表，核实最新限制，尽量接近各文案框上限，关键词加粗，先给完整稿审核。”
